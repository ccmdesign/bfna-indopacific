# BF-97 — Critical Minerals tab: CRM boxes + nickel chart scope

## Where the branching lives today

`components/infographics/AseanInfographic.vue` renders the Critical Minerals
tab as the "back" face of two `CardFlip` panels inside the sidebar's charts
tabpanel:

- **Card A** (world-share bars) — `CountryMineralShareBars.vue`, gated on
  `activeMinerals` (`MINERALS_BY_SLUG[slug]`). **Untouched by this ticket.**
- **Card B** (nickel flow) — `CountryMineralFlowBand.vue`, gated the same way.
  This is the chart the brief wants scoped to 4 countries.

Both panels currently share one visibility gate, `mineralsNullState = tab
=== 'minerals' && !activeMinerals.value`, which only catches Timor-Leste
(the one slug with **no** `MINERALS_BY_SLUG` entry at all) and swaps both
panels for a single "Not yet on the critical-minerals map" message.

Countries that *do* have a `MINERALS_BY_SLUG` entry but `hasMaterialData:
false` (Singapore, Brunei, Cambodia) fall through to
`CountryMineralFlowBand`'s own internal empty state ("Negligible direct
critical-mineral exports"), because `hasData` inside that component checks
`data.hasMaterialData`.

Thailand, Laos and Myanmar currently render the real chart (they have
`hasMaterialData: true` and real flow rows) — but per Feedback 2 they move to
the CRM box anyway. **The country list is a fixed editorial decision, not a
data-driven one** — `hasMaterialData`/`hasData` no longer gates which UI
Card B shows.

## New gating

A fixed slug set decides Card B's face, independent of `MINERALS_BY_SLUG`:

```ts
const NICKEL_CHART_SLUGS = new Set(['indonesia', 'malaysia', 'vietnam', 'philippines'])
const showsNickelChart = computed(() => !!activeSlug.value && NICKEL_CHART_SLUGS.has(activeSlug.value))
const crmNote = computed(() => activeSlug.value ? CRM_NOTES_BY_SLUG[activeSlug.value] : undefined)
```

- `showsNickelChart` true → render `CountryMineralFlowBand` inside
  `CountryChartCard`, plus the new scope caption line.
- else `crmNote` present (the other 7 slugs) → render the new
  `CountryCrmBox` inside the same `CountryChartCard` shell, same panel slot.
- `mineralsNullState` and the `asean-infographic__minerals-empty` block are
  removed entirely — every slug now resolves to one of the two branches
  above, including Timor-Leste (which has no `MINERALS_BY_SLUG` row but does
  get a `CRM_NOTES_BY_SLUG` row).
- Card A (world-share bars) visibility is decoupled from Card B: it keeps
  its own `activeMinerals` gate (`v-if="activeMinerals"` on
  `CountryMineralShareBars`), unchanged in spirit — Timor-Leste simply has no
  Card A content since it has no minerals record, same as before.

## CRM box data shape

New file `data/asean/critical-minerals-notes.ts`, generated by hand (not by
the mineral build script — this is editorial client copy, not BACI/USGS
data):

```ts
export interface CrmNote {
  leadIn: string       // short bold statement (the card's "title")
  lines: string[]      // supporting sentences, rendered as a list
  source?: string       // short citation, matches existing "Source: X" style
}
export const CRM_NOTES_BY_SLUG: Record<string, CrmNote> = { thailand: {...}, singapore: {...}, brunei: {...}, cambodia: {...}, laos: {...}, myanmar: {...}, timor_leste: {...} }
```

Copy is split at the client's own "lead clause: supporting detail(s)"
pattern into `leadIn` + `lines`. Myanmar's `source` cites the Böll article
(text citation, no inline link — matches how every other `source` prop in
this codebase is rendered as plain text, never a hyperlink).

## Component approach

New `components/asean/CountryCrmBox.vue`:
- Takes a `note: CrmNote` prop.
- Renders `leadIn` as a bold lead line (reusing `CountryChartCard`'s title
  slot is simpler — see below) and `lines` as short supporting paragraphs/list
  items, styled consistently with the existing translucent-white sidebar
  system (mirrors `CountryKeyFacts.vue`'s type scale, not a new palette).

Usage: swap `CountryChartCard`'s `title`/`eyebrow`/`meta`/`source` props for
the CRM variant and slot `CountryCrmBox` in as the body, in the exact same
`CardFlip` `#back` slot the chart currently occupies — so the "same card
slot/position" requirement is structural, not visual-only.

## Scope caption placement

Added to `CountryChartCard`'s existing `meta` line (right-aligned, small
text) for the 4 chart countries only:
`meta="All nickel-class exports by value · ore, matte, oxide sinter, refined"`
(replacing the current generic `meta="USD share by destination"`), so the
caption sits directly under the chart title without a new element. The
`source` prop stays `BACI HS07 V202601 (mineral HS6 codes), 2024` and gets
"; nickel-class HS6 codes" appended if needed for precision — final wording
decided at implementation time to fit the meta line's width constraints.
